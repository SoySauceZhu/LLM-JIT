# Gemma 3 270M IT：完整 validation 基线（v3，CUDA）

运行记录日期：2026-11-24（UTC）。分析日期：2026-11-24。本次评估未经微调的 `google/gemma-3-270m-it`，覆盖 2024 年 10 月全部 1,013 条 CFPB 房贷投诉。

**准确率 26.75%（271/1,013），五类 macro-F1=0.1591，有效输出率 83.61%（847/1,013）。** Student 已全部完成，未记录运行时异常。166 条最终失败全部为空回复；B、E 两类召回率均为零。当前导出尚未完成 DeepSeek Teacher 配对，因此 Teacher 一致率暂不报告。

## 数据、设置与核验

- 数据分区为 `validation`，采用 UTC 接收时间：`2024-10-01 ≤ 日期 < 2024-11-01`。实际首末记录为 `2024-10-01T00:18:49.000Z` 和 `2024-10-31T23:52:07.000Z`，原始序号 9,160—10,172。
- 类别数：A=106、B=84、C=562、D=215、E=46。没有抽样，没有微调，没有读取 test 进行评分。
- 模型 revision：`ac82b4e820549b854eebf28ce6dedaf9fdfa17b3`；CUDA、FP32、batch size 1、四 CPU 线程；使用 Gemma 原生 tokenizer/chat template。
- v3 提示词含完整分类指令和五个固定示例。贪心生成，每次最多 16 个新 token；无效输出允许重试一次。停止条件包含模型/tokenizer EOS 和 `<end_of_turn>`，只移除末尾停止 token 后严格解析 A–E。
- 正文截短继续使用固定 SmolLM2 tokenizer，超过 3,000 token 时保留前 2,000 和后 1,000；共 2 条被截短。已使用本地缓存的固定版本 tokenizer 离线重建全部输入清单，包括这 2 条的正文哈希，均与运行清单一致。
- 已检查 SQLite 完整性、账本与 JSON 配置一致性、CSV/清单/源数据的 1,013 个 ID 与顺序、参考标签、日期和 split；逐条核对首次/末次回复、最终标签、尝试次数。已从 CSV 独立重算自由生成和首 token 两组指标，并与账本核对 token 和耗时总量。
- `n_expected=1013`、`n_terminal=1013`、`n_pending=0`、`complete=true`、`provisional=false`。所有最终失败计错，主指标分母固定为 1,013；macro-F1 对五类等权。

## 总体结果

| 口径 | 正确数 / 总数 | 准确率 | 五类 macro-F1 | 有效输出率 |
|---|---:|---:|---:|---:|
| **自由生成：正式 Student baseline** | **271/1,013** | **26.75%** | **0.1591** | **83.61%** |
| 首 token A–E 五选一：独立诊断 | 292/1,013 | 28.83% | 0.1640 | 100.00% |
| 常量 C：类别不平衡诊断 | 562/1,013 | 55.48% | 0.1427 | 100.00% |

常量 C 仅作为解释类别分布的参照，不是按 history Teacher 标签拟合的正式多数类基线，也不是从 validation 拟合的新模型。Gemma 准确率比它低 28.73 个百分点，macro-F1 高 0.0163；两项指标需结合解读，不能因 macro-F1 略高就认为分类能力已经足够。

只保留 847 条合法回复时，正确率为 32.00%。这仅是条件性诊断，排除了失败样本，不作为主结果。即使假设全部 166 条空回复都被改为正确答案、其他预测不变，总准确率也最多达到 43.14%，仍低于常量 C。可见问题同时涉及格式遵循和合法回复中的分类错误。

## 空回复、重试和首 token 诊断

1,179 次推理尝试中，847 次为合法回复，332 次为无效回复，没有 `paused` 或其他运行时错误。847 条样本首次成功，166 条各尝试两次后失败，**重试恢复数为 0**。

332 次无效回复的原始文本都为 `""`，每次均记录 1 个输出 token。这与直接生成停止 token、随后被移除的表现相符；账本没有保存原始生成 token ID 或全词表分数，因此不能确定具体停止 token，也不能据此判定数值后端是根因。

第二次尝试额外消耗 239,595 个输入 token、166 个输出 token，累计尝试时间 12.36 秒，未产生恢复。本次两次尝试使用同一提示词和贪心设置；此处只报告观察结果，不修改冻结的重试策略。

首 token 诊断只在 A–E 候选中选最高分，不等同于实际自由生成，也不是完整受限解码实验。它在 166 条空回复中答对 21 条，使总正确数从 271 增至 292，准确率提高 2.07 个百分点；B、E 召回率仍为零。诊断标签未替换正式失败记录。

## 后续微调预期：有望减少空回复，需实验验证

**这类空回复有望通过后续任务微调得到改善，是待验证的学习目标，尚不是已经观测到的改善。** 使用 history 中合法的 Teacher 标签作监督，让模型学习在投诉输入后先生成 A–E 字母，再生成原生 `<end_of_turn>`。训练时让目标字母与结束符参与损失计算，提示词和 padding 不参与，以直接优化回答形式和标签选择。
